# 《衡垠世界图集》网页信息架构与视觉规范 · 交付对接说明

> 本文件只做规范转达与数据对接说明。**本 Agent 不修改 HTML/CSS/JS，不重排现有站点。**
> 网站技术架构、前端实现由网站 Agent 执行；数据层以本迁入库的正式索引为准。
> 附件截图只作目标形态参考，不是现有站点现状。

## 一、整体定位

同一份正式数据，同时支持三种使用方式：

- 阅读世界：地方志、历史叙述、设定文章。
- 探索世界：地图、地理层级、实体关联。
- 查阅知识：蛊虫、妖兽、秘境、组织等结构化档案。

不是三个独立网站；不是普通博客、不是纯数据库后台、不是旅游站。

## 二、全站框架（桌面端）

### 顶栏
- 衡垠世界图集标识。
- 全站搜索框。
- 当前所在模块。
- AI 资料包导出入口。
- 数据管理 / 建设状态入口。
- 保持简洁，不堆二级操作。

### 左侧主导航（固定，可展开二级）
1. 首页
2. 世界总览
3. 地理档案
4. 蛊道档案
5. 生灵图鉴
6. 秘境档案
7. 社会与组织
8. 历史档案
9. 跑团资料
10. 数据管理

### 中央内容区
- 展示当前页面核心内容。
- 正文控制行长，避免过长。
- 地图、表格、资料列表可按需占更大宽度。

### 右侧辅助面板（可收起）
- 当前实体基本信息。
- 资料来源。
- 设定状态。
- 相关实体。
- 章节目录。
- 关系跳转。
- 普通文章阅读页不必强行显示。

## 三、首页

- 项目标识与世界介绍。
- 全站搜索。
- 衡垠世界地图或地图主视觉（视觉中心，但不挤占其他入口）。
- 核心模块入口。
- 世界基本数据。
- 精选地方志与重要档案。
- 最近更新实体。
- 数据建设状态。
- 首页负责引导探索，不直接罗列全部数据库记录。

## 四、蛊道档案目录

### 四层结构
1. 来源类别：C-G 原著 / O-G 原创。
2. 转数：一转至九转；未知单独一组。
3. 实际流派：只列 `gu-index.json` 中真实存在的 `sect`；`null` 进“未标流派”，不得预先编造。
4. 蛊虫条目：名称、编号、转数、流派、核心能力摘要、来源状态。

默认排序：转数 → 流派 → 编号。支持名称、编号、来源类别、能力用途检索。

### 详情页
基础信息 → 能力机制 → 炼制与使用条件 → 真元消耗及限制（仅有可靠资料时）→ 战术用途 → 相关蛊虫 → 关联杀招/蛊方 → 来源与修订。

数据字段直接取 `Indexes/gu-index.json`；正文取 `content_file`。同一 `id` 不得在目录中复制出第二条记录。

## 五、生灵图鉴目录

### 先分区
- C-B 原著妖兽。
- R-B 参考物种（非本世界实存）。
- O-B 原创妖兽（本世界实存）。

### 检索维度
栖息环境、危险等级、体型、生态类型、是否携带蛊虫、是否与秘境关联。

### 详情页
- 优先连贯自然语言，再以表格呈现数值与比较数据。
- O-B 必须保留既有二十节结构。
- 携带蛊虫单独显示，明确“携带 / 寄生 / 共生 / 伴生 / 被动触发”，不得写成妖兽能像蛊师一样主动催动蛊虫。
- R-B 详情页固定提示“参考素材，非衡垠实存”。

数据取 `Indexes/beast-index.json` 与 `relationship-index.json`。

## 六、地图与地理档案

逐级浏览：

衡垠 → 大陆 → 国家 → 行政区 → 城市 → 城区 → 街道 → 社区 → 地点。

地图应支持：
- 层级切换。
- 图层显示/隐藏。
- 地点检索。
- POI 点击。
- 选中地点信息面板。
- 地点与相关实体跳转。

未完成的地图必须明标“尚未制作”，不得用虚构地图冒充正式地图。地图实体编号必须与统一数据层一致。

本迁入库已提供 `Indexes/realm-index.json`（64 条秘境登记），可作为秘境图层与关联面板的数据源；不提供城市/街道几何数据。

## 七、详情页统一顺序

1. 面包屑导航。
2. 实体名称和编号。
3. 分类、状态和核心标签。
4. 重点概述。
5. 核心属性信息。
6. 正文分章节。
7. 关联实体。
8. 来源和修订记录。

长文提供章节目录，侧边吸附但不挡正文。关系网络按需展开，不默认加载全库巨大关系图。

## 八、地方志页面

临江市、北城区、街道、社区等保留杂志式/地方志式阅读感：
- 有层次的中文大标题。
- 引导性概述。
- 连贯地理与历史描述。
- 解释性地图。
- 清楚统计数据。
- 交通、产业、人口、生活专题。
- 关联地点与组织入口。

不要把地方志全部改成属性表格；文字阅读体验与知识档案页区分。

## 九、视觉

- 纸白或温和米白底色。
- 深蓝灰主文字。
- 河流蓝用于地图与链接强调。
- 低饱和铜色少量装饰。
- 中文衬线标题，清晰无衬线正文。
- 线条、分隔、卡片边界克制。
- 有世界地图集、历史档案、专业百科质感。
- 避免过度渐变、发光、玻璃拟态、大面积彩色卡片、无意义动画。

## 十、响应式

- 桌面：左侧导航 + 中央内容 + 可选右侧面板。
- 平板：左侧导航收起或可展开侧栏；右侧面板改抽屉。
- 手机：单列正文、导航抽屉、筛选器折叠、地图信息用底部详情面板。
- 任何尺寸都必须保留明确页面导航能力。

## 十一、数据与页面契约

- 一条正式实体只保存一份；地图、搜索、目录、详情页引用同一 `id`。
- 关系只从 `relationship-index.json` 生成。
- 来源与资料状态在详情页可查。
- 缺失资料不得用假数据占位。
- 目录、分类、筛选由实际数据动态生成。
- 网站与 AI 导出资料使用同一数据源。
- 读取 `flags`：`C-G-274/462/643` 为非实体记录，目录应过滤或单列；4 组 `suspected_duplicate` 只标注、不自动合并；45 条扩展临时键只在“待确认”区出现。

## 十二、交付检查（网站 Agent 执行）

- 首屏是否清楚展示世界定位与搜索入口。
- 所有主要模块能否从左侧导航抵达。
- 蛊道目录能否按转数与流派浏览。
- 生灵目录能否按来源类别区分。
- 详情页是否有良好长文阅读体验。
- 地理地图能否逐级探索。
- 地方志是否保留叙事感。
- 关联实体能否互相跳转。
- 手机端导航与筛选是否可用。
- 是否存在重复数据源或重复实体档案。
