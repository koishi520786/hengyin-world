# 数据结构说明（简版）

> 完整字段定义见 **`data/DATA_SCHEMA.md`**；本文件只是项目根目录的速查指针。

## 一句话

`data/entities/*.json` 是唯一正式数据源；`world-index.json`、`relationships.json`、`manifest.json`、网页里的 `#kb-data` 数据岛、以及 `衡垠AI资料包.zip` 全部由 `tools/build_kb.py` 投影生成，**不存在第二份手工维护的实体数据**。

## 一条实体记录至少包含

| 字段 | 含义 |
|---|---|
| `id` | 唯一编号，全库不重复 |
| `name` / `type` / `type_label` / `category` | 名称、类型键、中文类型、大类 |
| `parent_id` | **父级关系**（地理／行政层级），与普通关联分开 |
| `status` | `existing` 原设定已有｜`proposed` 新增拟定｜`uncertain` 尚未确认｜`revised` 已修订 |
| `coverage` | `full` 完整档案｜`summary` 摘录概要｜`index` 仅索引｜`missing` 未建档 |
| `summary` / `content_file` | 简介、正文文件路径 |
| `route` / `entity_route` | 网站专题页、统一实体档案页 |
| `tags` / `relations` / `source` / `version` | 标签、关联 ID、来源（文件＋版本＋章节）、版本 |
| `attributes` | **按类型扩展**：城市有面积人口、秘境有 S/D/R/ST/DS、蛊虫有转数流派、妖兽有威胁等级……不强制同构 |

## 关联关系

`relationships.json` 每条边含 `from`、`to`、`type`、`kind`、`status`、`note`、`source`。
`kind=hierarchy` 为父级（由 `parent_id` 生成），`kind=association` 为普通关联；关系类型有 `part_of`、`located_in`、`has_entrance`、`habitat`、`predation`、`carries_gu`、`headquarters_in` 等，完整字典在文件内 `kinds` 字段。

## 目录

`entities/` 按类型分卷｜`gazetteers/` 地方志｜`rules/` 规则｜`sources/` 来源与统计口径｜`reports/` 冲突与缺失报告。

## 重建

```
python tools/build_kb.py            # 从原始资料全量抽取 + 生成 + 注入网页
python tools/build_kb.py --sync     # 只依据现有 data/ 重新生成索引、ZIP、网页数据岛
```

普通用户双击 `重新生成资料.bat` 即可（等价于 `--sync`）。
